## กติกาการระบุตัวตน

- ทุกคำตอบต้องระบุชื่อ AI และเวอร์ชันที่ใช้อย่างชัดเจน และ นเวลาปัจุจบัน
- ใช้รูปแบบ: `[AI: <ชื่อโมเดล / เวอร์ชัน>]` : วันเวลา
- สำหรับรอบงานจาก AI-Executor ต้องระบุเพิ่มทุกครั้ง:
  - `Executor Model: <provider/model/version>`
  - `Execution Runtime: <local/cloud + toolchain>`
  - `Report Timestamp: <ISO8601>`


### Design/Plan Challenge Rule (บังคับ)

- หากพบว่าคำสั่งขัดกับแผนที่อนุมัติ, แนวปฏิบัติวิศวกรรมที่ดี, หรือเสี่ยงต่อข้อมูล/regression:
  - ให้ **หยุดก่อนลงมือ**
  - ส่งรายงานโต้แย้งกลับมาเป็นหัวข้อ:
    1) `Conflict Point`
    2) `Why It's Risky`
    3) `Evidence`
    4) `Proposed Alternatives (A/B + trade-off)`
    5) `Recommendation`
    6) `Decision Needed`
- ห้ามลงมือเองเมื่อ conflict ระดับ High จนกว่า Owner อนุมัติ

## กติกาการบันทึกการสนทนา

- คุยกันเป็นภาษาไทย
- บันทึกทุกครั้งที่มีการสนทนา
- ใช้ไฟล์ `.md` เป็น conversation log
-
- รูปแบบบันทึกต้องเป็น:

```text
เวลา
[ชื่อผู้ใช้]
Q: ต้องบันทึก "ข้อความเต็ม"
[AI: <ชื่อโมเดล / เวอร์ชัน>]
A: ต้องบันทึก "แบบสรุป" และต้องมีหลักฐาน/อ้างอิงท้ายคำตอบเสมอ
```

## Evidence Rule (บังคับ)

- เมื่อ A ระบุว่ามีการ "ดำเนินการแล้ว / แก้ไขแล้ว / เพิ่ม / ลบ / เปลี่ยน"
  → ต้องมี Evidence เสมอ (ห้ามเว้น)

- Evidence ต้องเป็นอย่างน้อยหนึ่งในรายการต่อไปนี้:
  1) ไฟล์ที่ถูกเปลี่ยน พร้อมสรุปว่าเปลี่ยนอะไร (path + change summary)
  2) คำสั่งที่รัน พร้อมผลลัพธ์ที่ได้
  3) commit hash หรือ diff สรุป

- การระบุ path ไฟล์เฉย ๆ จะถือเป็น Evidence ได้
  ก็ต่อเมื่อระบุชัดว่า "ไฟล์นี้ถูกเปลี่ยน" และบอกการเปลี่ยนแปลงโดยสรุป


## รูปแบบเพื่อให้อ่านง่าย (ใช้เป็นมาตรฐาน)

- คั่นแต่ละชุด Q/A ด้วยบรรทัด `---`
- ถ้า A ยาวหรือมีหลายข้อ ให้จัดเป็น bullet ใต้ `A:` เช่น

```md
A: ...
- ข้อ 1
- ข้อ 2
- ข้อ 3
```

## ความสอดคล้องระหว่างแชทกับไฟล์

- เนื้อหาในไฟล์บันทึกต้อง "ตรงกับคำตอบที่ส่งในแชท" เป็นหลัก
- อนุญาตให้ปรับเฉพาะการจัดรูปแบบเพื่อให้อ่านง่าย (ขึ้นบรรทัดใหม่/ทำ bullet/จัดวรรคตอน) แต่ห้ามเพิ่ม/ตัดสาระสำคัญจนทำให้ข้อมูลไม่ตรงกัน
